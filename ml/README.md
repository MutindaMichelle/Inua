# Modelling Implementation — Career Mentorship Effectiveness Prediction

This is the modelling slice of the system implementation: dataset →
preprocessing → training/comparison → persisted model → prediction
function. It stops at a Python function that behaves like the Prediction
API (IR-02) — wiring it into an actual REST route, the React frontend, and
PostgreSQL is Sprint 3/4 work (system development), not modelling.

## Setup

```bash
pip install -r requirements.txt
```

## Run order

```bash
python generate_dataset.py   # 1. builds mentorship_sessions_sample.csv
python train_model.py        # 2. preprocesses, trains, compares, saves the model
python predict.py            # 3. smoke-tests the saved model on two sample sessions
```

## Files

| File | Role | Report section |
|---|---|---|
| `generate_dataset.py` | Builds the simulated, literature-grounded dataset, aligned to the logical schema (Figure 4.3) | 3.2.1, DR-01–DR-03 |

## A deliberate design decision worth knowing before you defend this

`career_support_score` and `psychosocial_score` exist in the generated
dataset (matching the `sessions` table in Figure 4.3) but are **excluded
from the model's feature set**. Both scores are derived directly from the
same granular variables used to build the effectiveness label, so training
on them would let the model shortcut around learning from real behavioural
data — inflating accuracy artificially. The model trains on the seven
granular variables instead (mentor experience, session duration,
interaction frequency, goal progress, communication score, overall rating,
experience level), and the two composite scores are kept only as
schema-level fields for dashboards and explainability (NFR-05).

## Current results (this run)

XGBoost: ~78% accuracy, modestly ahead of Random Forest (~77%) and AdaBoost
(~75%) — see `model_metadata.json` for the exact numbers from your run,
since the simulated dataset regenerates with a fixed seed but results can
shift slightly if `N_SESSIONS` in `generate_dataset.py` is changed. This is
intentionally not near-perfect: the effectiveness label includes injected
noise (Section 3.2.1), so a model that recovers the underlying signal at
~75–80% accuracy is behaving correctly, not underperforming.
